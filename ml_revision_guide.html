§ 01

Basic Data Checks

Before training anything, understand your data. These five checks are your non-negotiables.

1. Histogram — Distribution Check

Are values spread normally? Or is everything piled to one side? Histograms show the shape of each feature.

import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

df = pd.read_csv('data.csv')

# Plot histogram for all numeric columns
df.hist(figsize=(14, 10), bins=30, color='steelblue', edgecolor='white')
plt.suptitle('Feature Distributions')
plt.tight_layout()
plt.show()

# Or for a single column with seaborn
sns.histplot(df['target'], kde=True)
plt.show()

2. QQ Plot — Normality Check

If points follow the diagonal line → roughly normal. Tails curving away = non-normal. Many models assume normality.

import scipy.stats as stats

stats.probplot(df['feature'], dist="norm", plot=plt)
plt.title('QQ Plot')
plt.show()

# Or using statsmodels
import statsmodels.api as sm
sm.qqplot(df['feature'], line='45')
plt.show()

3. Box Plot — Outlier Detection

Points outside the whiskers = potential outliers. Great for spotting extreme values fast.

sns.boxplot(data=df, orient='h')
plt.show()

# For a single column
sns.boxplot(x=df['feature'])
plt.show()

4. Correlation Matrix — Feature Relationships

See which features move together. High correlation between features = multicollinearity risk. High correlation with target = good predictor.

corr = df.corr()

plt.figure(figsize=(10, 8))
sns.heatmap(corr, annot=True, fmt='.2f', cmap='coolwarm',
           center=0, linewidths=0.5)
plt.title('Correlation Matrix')
plt.show()

5. Variance Inflation Factor (VIF) — Multicollinearity

VIF > 5–10 means a feature is explained by others → consider dropping it. Critical for linear/logistic regression.

from statsmodels.stats.outliers_influence import variance_inflation_factor
from statsmodels.tools.tools import add_constant
import numpy as np

X = df.drop(columns=['target'])
X = add_constant(X)

vif_data = pd.DataFrame()
vif_data['Feature'] = X.columns
vif_data['VIF'] = [variance_inflation_factor(X.values, i)
                   for i in range(X.shape[1])]

print(vif_data.sort_values('VIF', ascending=False))
# Rule of thumb: VIF > 10 → drop or combine
§ 02

When to Reject (or Fix) Data

Highly Skewed Data

  • Skewness > |1| is a red flag
  • Linear models assume near-normality
  • Fix: log transform, sqrt, Box-Cox
  • Tree models are more tolerant

Too Many Missing Values

  • > 40–50% missing in a column → consider dropping
  • Check if data is missing at random (MAR) or not
  • Fix: impute (mean/median/mode) or drop

Multicollinearity

  • VIF > 10 → features overlap too much
  • Breaks linear/logistic regression coefficients
  • Fix: drop one feature, PCA, or use tree models

Target Leakage

  • A feature that contains info from the future
  • Model looks great in training, fails in production
  • Example: using "refund_date" to predict "churn"
  • Fix: strict temporal train/test split, domain check

Imbalanced Dataset (Classification)

  • 99% class-0, 1% class-1 → model predicts all 0s
  • Accuracy is misleading here
  • Fix: SMOTE, class_weight='balanced', use F1/AUC
# Check skewness
print(df.skew())  # |value| > 1 is high skew

# Check missing values
print(df.isnull().mean() * 100)  # % missing per column

# Check class imbalance
print(df['target'].value_counts(normalize=True))
§ 03

Handling Outliers

Remove vs Cap vs Transform — When to use what?

  • Remove — When outliers are data errors (typos, sensor glitches). Small datasets only.
  • Cap (Winsorize) — When outliers are real but extreme. Clip to a reasonable range.
  • Transform — When the whole distribution is skewed. Log/sqrt compresses large values.

IQR Method — Detect Outliers

Values below Q1 − 1.5×IQR or above Q3 + 1.5×IQR are considered outliers.

Q1 = df['feature'].quantile(0.25)
Q3 = df['feature'].quantile(0.75)
IQR = Q3 - Q1

lower = Q1 - 1.5 * IQR
upper = Q3 + 1.5 * IQR

# Remove outliers
df_clean = df[(df['feature'] >= lower) & (df['feature'] <= upper)]

Capping (Winsorizing) — Clip Extreme Values

from scipy.stats.mstats import winsorize
import numpy as np

# Winsorize: cap bottom 5% and top 5%
df['feature_capped'] = winsorize(df['feature'], limits=[0.05, 0.05])

# Or manually clip
df['feature_capped'] = df['feature'].clip(lower=lower, upper=upper)

Log Transformation — Compress Skewed Data

import numpy as np

# Apply log1p (handles zeros safely: log(1 + x))
df['feature_log'] = np.log1p(df['feature'])

# Sqrt transform (less aggressive than log)
df['feature_sqrt'] = np.sqrt(df['feature'])

# Check if skew improved
print('Before:', df['feature'].skew())
print('After:',  df['feature_log'].skew())
§ 04

Which Model to Use

Linear Regression

  • Target is continuous (price, sales, time)
  • Relationship is roughly linear
  • You want to explain coefficients
  • Fast, interpretable, great baseline

Logistic Regression

  • Target is binary (0/1, Yes/No, Churn/No)
  • Need probability outputs
  • Features are roughly linearly separable
  • Interpretable, fast, great baseline classifier

Random Forest

  • Non-linear relationships
  • Mixed feature types (numeric + categorical)
  • Resistant to outliers
  • Handles missing values better than LR
  • Good when you have moderate-sized data

LightGBM

  • Large datasets (millions of rows)
  • Tabular data, structured features
  • Need speed + accuracy
  • Handles missing values natively
  • Kaggle/production workhorse

Linear Regression Continuous ✗ No ⚡ Very Fast ★★★ High Baseline, price prediction
Logistic Regression Binary ✗ Limited ⚡ Very Fast ★★★ High Churn, fraud (baseline)
Random Forest Both ✓ Yes ⚡⚡ Moderate ★★ Medium General-purpose, noisy data
LightGBM Both ✓ Yes ⚡⚡⚡ Fast ★ Low Large data, competitions
§ 05

Feature Engineering

Good features > fancy models. This is often the highest-leverage step.

One-Hot Encoding — Categorical to Binary Columns

Use for nominal categories (no natural order: city, gender, color).

# pandas
df_encoded = pd.get_dummies(df, columns=['city', 'category'], drop_first=True)

# sklearn (preferred in pipelines)
from sklearn.preprocessing import OneHotEncoder

ohe = OneHotEncoder(drop='first', sparse_output=False)
encoded = ohe.fit_transform(df[['city']])

Label Encoding — For Ordinal Categories

Use when there's a natural order: Low → Medium → High. Don't use for nominals.

from sklearn.preprocessing import LabelEncoder

le = LabelEncoder()
df['priority_encoded'] = le.fit_transform(df['priority'])
# low=0, medium=1, high=2

Feature Scaling — StandardScaler

Critical for linear/logistic regression and distance-based models. Tree models don't need this.

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()  # mean=0, std=1
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled  = scaler.transform(X_test)  # NEVER fit on test!

# MinMaxScaler if you want [0, 1] range instead
from sklearn.preprocessing import MinMaxScaler

Handling Missing Values — SimpleImputer

from sklearn.impute import SimpleImputer

# Numeric: fill with median (robust to outliers)
num_imputer = SimpleImputer(strategy='median')
X_train[num_cols] = num_imputer.fit_transform(X_train[num_cols])
X_test[num_cols]  = num_imputer.transform(X_test[num_cols])

# Categorical: fill with most frequent
cat_imputer = SimpleImputer(strategy='most_frequent')
X_train[cat_cols] = cat_imputer.fit_transform(X_train[cat_cols])
Pipeline tip: Combine imputer + scaler + model in a Pipeline to prevent data leakage and make production deployment easier.
§ 06

Important Model Parameters

📐 Linear Regression

fit_intercept Whether to add a bias term. Almost always True.
normalize Deprecated — use StandardScaler instead.

No tuning required. Focus on feature quality instead.

🔵 Logistic Regression

C Regularization strength. Smaller C = stronger regularization (less overfitting).
penalty 'l1' (sparse), 'l2' (default), 'elasticnet'.
max_iter Increase if convergence warning appears.
class_weight 'balanced' for imbalanced datasets.

🌲 Random Forest

n_estimators Number of trees. More = better, slower. Start with 100–300.
max_depth Max tree depth. Deeper = more complex. None = unlimited (overfit risk).
min_samples_split Min samples needed to split a node. Higher = simpler tree.
max_features 'sqrt' for classification, 'log2' or None for regression.

⚡ LightGBM

num_leaves Controls complexity. Default 31. Higher = more complex (overfit risk).
learning_rate Step size. Lower = better generalization but slower. Try 0.05–0.1.
n_estimators Number of boosting rounds. Use early stopping to find optimum.
min_child_samples Regularization. Higher = simpler model. Default 20. 
from sklearn.linear_model import LinearRegression, LogisticRegression
from sklearn.ensemble import RandomForestClassifier
import lightgbm as lgb

# Linear Regression
lr = LinearRegression(fit_intercept=True)

# Logistic Regression
logit = LogisticRegression(C=1.0, penalty='l2',
                             class_weight='balanced', max_iter=1000)

# Random Forest
rf = RandomForestClassifier(n_estimators=200, max_depth=10,
                              min_samples_split=5, random_state=42)

# LightGBM
lgbm = lgb.LGBMClassifier(num_leaves=31, learning_rate=0.05,
                             n_estimators=500, min_child_samples=20)
§ 07

Model Evaluation

Key rule: Always evaluate on a held-out test set you've never touched during training.

Regression Metrics

  • RMSE — Root Mean Squared Error. Same units as target. Penalizes large errors.
  • R² — % of variance explained. 1.0 = perfect, 0 = predicts mean, negative = worse than mean.
  • MAE — Mean Absolute Error. Easier to interpret, less sensitive to outliers.
from sklearn.metrics import mean_squared_error, r2_score, mean_absolute_error
import numpy as np

y_pred = model.predict(X_test)

rmse = np.sqrt(mean_squared_error(y_test, y_pred))
r2   = r2_score(y_test, y_pred)
mae  = mean_absolute_error(y_test, y_pred)

print(f'RMSE: {rmse:.4f}')
print(f'R²:   {r2:.4f}')
print(f'MAE:  {mae:.4f}')

Classification Metrics

  • Accuracy — Misleading when classes are imbalanced.
  • Precision — Of all predicted positives, how many are actually positive? (Avoid false alarms)
  • Recall — Of all actual positives, how many did we catch? (Avoid missing positives)
  • F1 — Harmonic mean of precision & recall. Use when both matter.
  • ROC-AUC — Overall discriminability. 0.5 = random, 1.0 = perfect.
from sklearn.metrics import (accuracy_score, precision_score,
                                recall_score, f1_score,
                                roc_auc_score, classification_report)

y_pred      = model.predict(X_test)
y_pred_prob = model.predict_proba(X_test)[:, 1]  # for ROC-AUC

print(f'Accuracy:  {accuracy_score(y_test, y_pred):.4f}')
print(f'Precision: {precision_score(y_test, y_pred):.4f}')
print(f'Recall:    {recall_score(y_test, y_pred):.4f}')
print(f'F1:        {f1_score(y_test, y_pred):.4f}')
print(f'ROC-AUC:   {roc_auc_score(y_test, y_pred_prob):.4f}')

# Full breakdown
print(classification_report(y_test, y_pred))
ScenarioPreferred MetricWhy
Balanced classesAccuracy, F1Reliable when classes are equal
Imbalanced classesROC-AUC, F1Accuracy is misleading here
Cost of false positives highPrecisionSpam filter — don't block valid emails
Cost of false negatives highRecallCancer detection — don't miss cases

§ 08

If Model Performance is Bad

Underfitting (High Bias)

  • Train error is also high
  • Model is too simple
  • Fixes:
  • → Add more features / interactions
  • → Increase model complexity (depth, leaves)
  • → Train longer (more estimators)
  • → Try a more powerful model (LightGBM)
  • → Reduce regularization (higher C, lower lambda)

Overfitting (High Variance)

  • Train error low, test error high
  • Model memorized training data
  • Fixes:
  • → Add regularization (L1/L2, lower C)
  • → Reduce max_depth, increase min_samples
  • → Get more training data
  • → Drop noisy / irrelevant features
  • → Use cross-validation properly
General checklist: Bad data quality → fix features first. Then try model. Then tune.

GridSearchCV — Hyperparameter Tuning

Systematically try combinations of parameters and pick the best.

from sklearn.model_selection import GridSearchCV
from sklearn.ensemble import RandomForestClassifier

param_grid = {
    'n_estimators':    [100, 200, 300],
    'max_depth':       [5, 10, None],
    'min_samples_split': [2, 5, 10]
}

rf = RandomForestClassifier(random_state=42)
grid_search = GridSearchCV(rf, param_grid, cv=5,
                              scoring='roc_auc', n_jobs=-1)
grid_search.fit(X_train, y_train)

print('Best params:', grid_search.best_params_)
print('Best AUC:',    grid_search.best_score_)

best_model = grid_search.best_estimator_

RandomizedSearchCV — Faster Alternative

When you have many parameters, random sampling is faster than exhaustive grid search.

from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import randint, uniform

param_dist = {
    'n_estimators': randint(100, 500),
    'max_depth':    randint(3, 20),
    'learning_rate': uniform(0.01, 0.2)  # for LightGBM
}

random_search = RandomizedSearchCV(model, param_dist,
                                     n_iter=50, cv=5,
                                     scoring='roc_auc',
                                     random_state=42, n_jobs=-1)
random_search.fit(X_train, y_train)
print(random_search.best_params_)
Interview tip: If performance is bad, always say: "First I'd check the data, then evaluate if it's underfitting or overfitting, then tune." Don't jump straight to "try a different model."
