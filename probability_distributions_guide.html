Foundation

What is a Probability Distribution?

A probability distribution describes how the values of a random variable are spread — it tells you the likelihood of each possible outcome. In product analytics, distributions are the mathematical backbone of experimentation, modeling user behavior, and making decisions under uncertainty.

Discrete distributions
Countable outcomes
The random variable can only take specific, countable values (integers). You count events, not measure them continuously.
Examples: number of clicks, installs, crashes, conversions, sessions
Continuous distributions
Measurable outcomes
The random variable can take any value within a range. You measure time, duration, revenue, or probability.
Examples: session duration, time-to-churn, ARPU, conversion rate
PMF
Probability Mass Function
For discrete distributions. Gives exact probability P(X = k) for each value k. All probabilities sum to 1.
PDF
Probability Density Function
For continuous distributions. P(X = x) = 0 for any exact value. Area under curve = 1. Use for ranges: P(a ≤ X ≤ b).
CDF
Cumulative Distribution Function
F(x) = P(X ≤ x). Works for both. Used to answer "probability of AT MOST x" — critical for p-values and confidence intervals.
Why It Matters in Product Analytics
A/B Testing
Binomial models conversions; Normal approximation powers z-tests; Beta models CTR posteriors
User Behavior
Geometric: sessions until purchase. Poisson: crashes/day. Exponential: time between sessions
Retention
Exponential & Geometric model time-to-churn. Survival analysis builds on these foundations
Revenue Metrics
Normal approximates ARPU distributions. Log-normal models revenue (right-skewed)
Bayesian Testing
Beta distribution is the conjugate prior for Bernoulli/Binomial — updates with each observation
Risk Estimation
Model rare failure events with Poisson. Use Exponential for time-to-failure in reliability
Discrete · 01
Bernoulli
A single trial with exactly two outcomes: success (1) or failure (0).
Definition & When to Use
Models a single binary event. The building block of all other discrete distributions. Use when you have one trial with yes/no, click/no-click, convert/bounce outcomes.

Think of it as the "atom" — Binomial is just n repeated Bernoulli trials.
Assumptions
  • Exactly one trial
  • Only two possible outcomes (success / failure)
  • Constant probability p of success
  • Outcome is binary (1 or 0)
Formula (PMF)
P(X = 1) = p ← probability of success P(X = 0) = 1 − p ← probability of failure Or compactly: P(X = k) = pᵏ · (1−p)^(1−k) where k ∈ {0, 1}
Key Statistics
Mean
p
Variance
p(1−p)
Std Dev
√p(1−p)
Shape
2 bars
PMF — Bernoulli(p = 0.25)
n=1, p=0.25
Product & Google Examples
Ad Click: Did user click the Google ad? p = CTR (e.g. 2%)
App Install: Did user install the recommended Play Store app? p = install rate
Conversion: Did user purchase after viewing a promotion? p = conversion rate
A/B Test Unit: Each user's binary outcome (converted / not) is a Bernoulli trial
Mental Model — Recognize it when...
You hear "did the user..." or "binary outcome". Any single yes/no event. It's the default starting point before you scale to n trials (Binomial).
single trial click / no-click convert / bounce binary outcome success / failure
Discrete · 02
Binomial
Number of successes in n independent Bernoulli trials.
Definition & When to Use
The Binomial is n repeated Bernoulli trials. Use when: you run a fixed number of trials, each trial is independent, success probability p is constant, and you're counting how many successes occurred.

This is the workhorse of A/B testing with binary outcomes.
Assumptions
  • Fixed number of trials n
  • Each trial independent
  • Constant probability p per trial
  • Binary outcome per trial
  • Counting total successes X
Formula (PMF)
P(X = k) = C(n, k) · pᵏ · (1−p)^(n−k) where C(n, k) = n! / (k! · (n−k)!) ← "n choose k" n = number of trials p = probability of success per trial k = number of successes (0 ≤ k ≤ n)
Key Statistics
Mean
np
Variance
np(1−p)
Std Dev
√np(1−p)
Shape
Bell-like
PMF — Binomial(n=20, p=0.30)
E[X]=6, Var=4.2
Product & Google Examples
A/B Test: Out of 1,000 users shown new feature, how many convert? n=1000, p=conversion rate
Play Store: Of 50 users who see app recommendation, how many install? n=50, p=0.15
Email Campaign: Of 10,000 users emailed, how many open it? n=10000, p=open rate
Retention: Of 500 users from Jan cohort, how many are active in Feb?
Mental Model — Recognize it when...
You hear "out of N users, how many...". Fixed sample size, binary per-user outcome. If n is large and p is small, Poisson is a useful approximation (λ = np).
n trials fixed how many out of N A/B conversion retention count install count
Discrete · 03
Geometric
Number of trials until the first success. Memoryless.
Definition & When to Use
Use when you're asking "how long until the first success?" The key property is memorylessness: past failures don't change future probability. Each trial is a fresh start.

The discrete counterpart to the Exponential distribution.
Assumptions
  • Trials are independent
  • Constant probability p per trial
  • Counting trials until first success
  • Memoryless: P(X > m+n | X > m) = P(X > n)
Formula (PMF)
P(X = k) = (1−p)^(k−1) · p ← k trials until first success where k = 1, 2, 3, ... p = probability of success on each trial CDF: P(X ≤ k) = 1 − (1−p)ᵏ
Key Statistics
Mean
1/p
Variance
(1−p)/p²
Std Dev
√(1−p)/p
Shape
Decreasing
PMF — Geometric(p = 0.25)
E[X]=4, decreasing probability
Product & Google Examples
First Purchase: How many app sessions until user makes their first in-app purchase?
Feature Discovery: How many Play Store visits until user discovers the subscription feature?
Ad Conversion: How many ad impressions before the first click? p = CTR
Support: How many chatbot interactions until user's issue is resolved?
Mental Model — Recognize it when...
You hear "how many attempts until the first...". Think waiting, retrying, time-to-first-event in discrete steps. If the unit is time (not discrete tries), switch to Exponential.
first success how many until sessions to purchase memoryless waiting time (discrete)
Discrete · 04
Poisson
Number of rare events in a fixed time/space interval.
Definition & When to Use
Models rare, independent events occurring at a constant average rate λ over a fixed interval. Unique property: mean equals variance (both = λ). Great approximation for Binomial when n is large and p is small (λ = np).
Assumptions
  • Events are independent
  • Constant average rate λ per interval
  • Two events can't occur simultaneously
  • Fixed observation interval
  • Events are relatively rare
Formula (PMF)
P(X = k) = (e^(−λ) · λᵏ) / k! where λ = average number of events per interval (rate) k = number of events (0, 1, 2, ...) e ≈ 2.71828 (Euler's number) Note: Mean = Variance = λ (diagnostic check!)

√λ

Right-skewed

Product & Google Examples
App Crashes: Number of app crashes per hour on Google Play. λ = avg crashes/hour
Server Requests: API calls arriving per second to a Google Maps endpoint
Bug Reports: Number of critical bug reports received per day
Rare Events: Number of users hitting rate limits per minute
Mental Model — Recognize it when...
You hear "events per unit time/space" or "rare occurrences". The signature: you know the rate λ, you're counting events, and mean ≈ variance. If variance >> mean, use Negative Binomial.
events per hour/day crashes per session rare events fixed interval mean = variance
Continuous · 05
Uniform
Every value in [a, b] is equally likely. Maximum uncertainty.
Definition & When to Use
The simplest continuous distribution: flat probability across a range. Used when you have no prior information favoring any value over another. Also the default "uninformed prior" in Bayesian analysis: Beta(1,1) = Uniform(0,1).
Assumptions
  • Continuous outcomes within bounded range [a, b]
  • All values equally likely
  • No information favoring any value
  • Strict bounds (a and b are known)
Formula (PDF & CDF)
PDF: f(x) = 1/(b − a) for a ≤ x ≤ b f(x) = 0 otherwise CDF: F(x) = (x − a)/(b − a) for a ≤ x ≤ b F(x) = 0 for x < a F(x) = 1 for x > b
Key Statistics
Mean
(a+b)/2
Variance
(b−a)²/12
Std Dev
(b−a)/√12
Shape
Flat / Rectangular
PDF — Uniform(a=0, b=1)
Mean=0.5, flat density
Product & Google Examples
Bayesian Prior: Before running an A/B test, assume CTR is equally likely to be anywhere in [0%, 100%] — use Uniform as uninformed prior (= Beta(1,1))
Random Assignment: A/B test group assignment uses Uniform(0,1) to randomly assign users to control/treatment
Simulation: Monte Carlo methods use Uniform random variables as the base for generating other distributions
Mental Model — Recognize it when...
You hear "equally likely" or "no prior information". Also appears as a building block: random numbers are Uniform, and you transform them to simulate other distributions.
equally likely no prior info random assignment uninformed prior simulation base
Continuous · 06
Normal (Gaussian)
The bell curve. Symmetric, defined by μ and σ. The backbone of classical statistics.
Definition & When to Use
The most important distribution in statistics. Use when data is symmetrically distributed around a mean. By the Central Limit Theorem (CLT): sample means of any distribution approach Normal as n → ∞. This is why z-tests work for large samples.
Assumptions & Key Facts
  • Continuous, symmetric around μ
  • 68% of data within ±1σ
  • 95% of data within ±2σ
  • 99.7% of data within ±3σ
  • Standard Normal: μ=0, σ=1 (z-scores)
Formula (PDF)
f(x) = (1 / (σ · √(2π))) · exp(−(x − μ)² / (2σ²)) μ = mean (center of distribution) σ = standard deviation (spread) σ² = variance Z-score: z = (x − μ) / σ ← standardize to N(0,1)
Key Statistics
Mean
μ
Variance
σ²
Std Dev
σ
Shape
Symmetric bell
PDF — Normal(μ=0, σ=1) — Standard Normal
68-95-99.7 rule applies
Product & Google Examples
ARPU: Average Revenue Per User across a large user base approximates Normal by CLT. Use for hypothesis testing revenue lift.
Session Duration: User session durations cluster around a mean. Compare treatment vs control using a z-test or t-test.
A/B Test Results: Sample means of conversion rates approximate Normal (CLT). Foundation of z-tests for significance.
Model Residuals: Linear regression assumes normally distributed residuals — diagnostic check in modeling.
Mental Model — Recognize it when...
You hear "average metric", "compare means", or large sample sizes. CLT means almost any mean of a large enough sample becomes Normal. Also: if you're using z-tests or t-tests, you're implicitly assuming Normal.
bell curve symmetric CLT applies z-test / t-test compare means large n
Continuous · 07
Exponential
Time between events in a Poisson process. Continuous & memoryless.
Definition & When to Use
Models time until the next event when events arrive at a constant Poisson rate λ. Key property: memoryless — the probability of an event in the next t minutes doesn't depend on how long you've already been waiting.

Think of it as the continuous analog of the Geometric distribution.
Assumptions
  • Continuous time variable (not discrete counts)
  • Events arrive at constant rate λ
  • Memoryless: P(T > s+t | T > s) = P(T > t)
  • Events are independent
  • Right-skewed: most wait times short, few very long
Formula (PDF & CDF)
PDF: f(x) = λ · e^(−λx) for x ≥ 0 λ = rate (events per unit time) CDF: F(x) = 1 − e^(−λx) ← P(event happens within time x) Mean = 1/λ (average wait time) Var = 1/λ²
Key Statistics
Mean
1/λ
Variance
1/λ²
Std Dev
1/λ
Shape
Right-skewed
PDF — Exponential(λ = 0.5)
Mean wait = 1/λ = 2 units
Product & Google Examples
Time to Churn: Days until a user becomes inactive. λ = churn rate per day. P(churn within 7 days) = 1 − e^(−7λ)
Session Gap: Time between consecutive user sessions on Google Play. Model inter-session time as Exponential.
Server Latency: Time until next API request to a backend server — foundational for queuing theory and load modeling.
Survival Analysis: Combined with Poisson, drives Cox proportional hazard models for user lifecycle analysis.
Mental Model — Recognize it when...
You hear "time until...", "days before...", or "how long until churn/purchase". Continuous time, single event. If counting events (not time), use Poisson. If discrete trials (not continuous), use Geometric.
time until event days to churn inter-arrival time survival analysis memoryless
Continuous · 08
Beta
Distribution over probabilities [0,1]. The engine of Bayesian A/B testing.
Definition & When to Use
The Beta distribution models unknown probabilities and proportions. Defined on [0,1]. It's the conjugate prior for Bernoulli/Binomial — meaning: if your prior is Beta(α, β) and you observe s successes and f failures, your posterior is Beta(α + s, β + f). Updates beautifully.
Assumptions & Bayesian Role
  • Outcome is a probability or proportion ∈ [0,1]
  • Shape controlled by α (successes) and β (failures)
  • α=β=1 → Uniform (completely uninformed prior)
  • Larger α+β → more concentrated (more certainty)
  • Conjugate prior: Beta prior × Binomial likelihood = Beta posterior
Formula (PDF)
f(x; α, β) = x^(α−1) · (1−x)^(β−1) / B(α, β) where B(α, β) = Γ(α)·Γ(β) / Γ(α+β) ← normalizing constant α = shape (successes + 1 with uniform prior) β = shape (failures + 1 with uniform prior) Bayesian update rule: Prior: Beta(α, β) Observe: s successes, f failures Posterior: Beta(α + s, β + f)
Key Statistics
Mean
α/(α+β)
Variance
αβ/(α+β)²(α+β+1)
Mode
(α−1)/(α+β−2)
Shape
Flexible
PDF — Beta with varying α, β parameters
Shape changes with data observed
Product & Google Examples
Bayesian A/B Testing: Model CTR as Beta. Control: 100 conversions / 1000 views → Beta(101, 901). Posterior mean = 10%. Directly compare distributions to get P(Treatment > Control).
Conversion Rate Estimate: Early in an experiment, prior Beta(1,1) (uninformed). After 50 conversions from 200 → posterior Beta(51, 151). Mean = 25%.
Bandits: Thompson Sampling for multi-armed bandits uses Beta posteriors to balance explore/exploit in feature rollouts.
CTR Estimation: Ads team models expected CTR per ad using Beta priors updated from historical impressions/clicks.
Mental Model — Recognize it when...
You're modeling an unknown rate or probability (not an observed count). In Bayesian A/B testing, you never model "how many clicked" (that's Binomial) — you model "what is the true CTR?" (that's Beta). As data accumulates, Beta narrows and concentrates.
unknown probability Bayesian A/B test CTR posterior proportion ∈ [0,1] Thompson sampling conjugate prior

Choosing the Right Distribution

Scan these trigger questions to quickly identify which distribution your problem calls for.

Did the user click / convert / install? (One event)
→ Bernoulli(p)
Single binary outcome. p = known or estimated probability.
How many users out of N converted?
→ Binomial(n, p)
Fixed n, binary outcome per user, counting successes.
How many sessions until the first purchase?
→ Geometric(p)
Counting discrete trials to first success. Mean = 1/p.
How many crashes/errors per hour?
→ Poisson(λ)
Rare events at constant rate over fixed interval.
No prior info — every value equally plausible?
→ Uniform(a, b)
Uninformed prior or random generation base.
Comparing average revenue or session duration?
→ Normal(μ, σ²)
CLT: large-sample means are Normal. Use z-test.
How many days until a user churns?
→ Exponential(λ)
Continuous time until event. Memoryless property.
What is the true conversion rate in a Bayesian A/B test?
→ Beta(α, β)
Modeling an unknown probability. Updates with data.
n is very large, p is very small (rare event)?
→ Poisson(λ=np)
Binomial approximation when n→∞, p→0, np constant.
Mean ≈ Variance in count data?
→ Poisson(λ)
Diagnostic signature of Poisson. If Var >> Mean, use Negative Binomial.

Common Mistakes

Mistakes that analysts make when applying probability distributions in product and experimentation contexts.

⚠
Using Normal for small samples
Applying z-tests when sample sizes are small (n < 30). The CLT hasn't kicked in, and the Normal approximation can be poor — especially for binary metrics with extreme p values.
Fix: Use t-test for small continuous samples. For binary outcomes with small n, use exact Binomial test or Fisher's exact test.
⚠
Forgetting Poisson requires Mean ≈ Variance
Fitting a Poisson model to over-dispersed count data where Variance >> Mean (common in user behavior data). This produces underestimated standard errors and inflated significance.
Fix: Check Var/Mean ratio (called the Dispersion Index). If >> 1, use Negative Binomial distribution instead.
⚠
Confusing Geometric (discrete) and Exponential (continuous)
Geometric counts discrete trials (sessions, clicks); Exponential models continuous time (days, minutes). Using one when the other is appropriate leads to wrong parameter estimation.
Fix: Ask — "Is the unit a countable event or a continuous time measure?" Discrete → Geometric. Continuous → Exponential.
⚠
Treating A/B test metrics as independent when they're not
Each user may have multiple sessions/events. Treating each event as an independent Bernoulli trial when they're correlated (same user) violates independence assumptions and inflates sample size.
Fix: Use user-level randomization (not event-level). Analyze at the user grain, not the event grain.
⚠
Peeking at A/B test results before reaching sample size
Running significance tests repeatedly as data comes in dramatically inflates false positive rates. With α=0.05, peeking 10 times → true false positive rate ≈ 40%.
Fix: Pre-specify sample size and test duration. Use sequential testing methods (e.g., SPRT) if early stopping is genuinely needed.
⚠
Ignoring the difference between p-value and effect size
At Google's scale (millions of users), trivially small effects (0.001% lift) can achieve p < 0.05. Statistical significance ≠ practical significance. Shipping a 0.001% CTR improvement may cost more than the revenue gained.
Fix: Always define a Minimum Detectable Effect (MDE) and calculate business impact. Report confidence intervals alongside p-values.
